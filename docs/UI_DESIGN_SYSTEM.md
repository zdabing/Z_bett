# Bettbox UI 设计规范 v2（已实现）

本规范以 2026-10-25 概览 v1 的浅绿界面为视觉基准，覆盖概览、代理、连接、订阅、脚本、资源、工具箱、日志、设置。2026-10-25 已按本规范实现九个 LuCI 页面，并更新到测试路由器。独立设计稿仍使用模拟数据；正式页面使用路由器 RPC 与 Mihomo API。

## 1. 布局与响应式

核心原则：手机利用有效宽度，PC 随视口展开；主导航和常用操作直接可见，避免文字被压成逐字竖排。

| 视口 | 外层左右边距 | 内容间距 | 页面组织 |
| --- | --- | --- | --- |
| 320–599px | 12px | 12px | 单列；状态摘要可 2 列；节点在 360px 起可 2 列 |
| 600–1023px | 20px | 16px | 1–2 列，表格按实际空间切换 |
| 1024–2239px | 24px | 20px | 流式内容，避免固定 1200/1440px 容器制造大面积空白 |
| ≥2240px | 至少 32px | 24px | 内容最大 2160px，保持表格与表单的可读性 |

- 外层边距只收一次。卡片相对内容区直接对齐，不叠加主题容器、cbi-map、cbi-section 的多层横向 padding。
- 布局使用 `minmax(0, 1fr)`；所有可能收缩的 flex/grid 子项设置 `min-width: 0`。
- 手机页面本身不得横向滚动。代码编辑器可在自身内部横向滚动；长域名、IPv6、日志正文在组件内折行。
- 主导航 PC 为单行；小于 600px 为 **两行、每行最多 5 项**，九个页面全部可见，不收进汉堡菜单，不逐字换行，不依赖横向滚动条。
- 主导航文字 `white-space: nowrap; flex-shrink: 0`，保留清楚的当前页标记。主路由器菜单与 Bettbox 页签分开。
- 手机不将整个 PC 页面缩小，也不对 body 使用 transform/zoom 适配。
- 有固定底部操作栏时，内容留出按钮高度、上下边距和 `env(safe-area-inset-bottom)`，避免最后一项被遮住。

## 2. 色彩与排版

| Token | 浅色值 | 用途 |
| --- | --- | --- |
| background | `#f0f4f1` | 页面底色 |
| surface | `#ffffff` | 信息面板 |
| surface-subtle | `#f7faf7` | 次级区、代码区、未选中节点 |
| text-primary | `#233c33` | 标题、主要数值 |
| text-secondary | `#62756a` | 辅助内容、标签 |
| text-muted | `#7a887f` | 时间、次要元信息；不可用于关键小字 |
| accent | `#327563` | 主要操作、选中状态、焦点 |
| accent-subtle | `#eaf3ed` | 选中节点、状态背景 |
| border | `#dfe8e1` | 分割线、控件边界 |
| warning | `#956622` | 超时、有限可用 |
| danger | `#b34646` | 失败、危险操作 |

- 优先继承 LuCI 主题字体；独立设计稿使用 Noto Sans SC / Microsoft YaHei / 系统 sans-serif。
- PC 页面标题 26px/650，手机 22px/650；面板标题 16px/600；正文 14px；手机可编辑输入 16px，避免浏览器自动放大。
- 说明文字至少 12px。主要速率和计数 28–34px，使用 tabular-nums。IP、端口、时间、代码可用等宽字体。
- 长名称最多 2 行或单行省略，并提供展开详情；不得拆成单字竖排。完整名称仍能在详情中读取。
- 全站采用一致的线性 SVG 图标，18–20px、1.7px 描边。订阅提供的图标单独约束尺寸，加载失败有占位，不让 emoji 影响布局宽度。

## 3. 通用组件

- 面板：圆角 12–14px、1px 细边框、极轻阴影；手机内边距 14–16px，PC 20–24px。
- 按钮：手机最小触摸区域 44×44px，标签保持横排。测试、刷新、应用等高频操作有可见文字；图标按钮必须有可访问名称。
- 选中节点：浅绿背景、强调边框、勾选标记，保持深色文字；不能只用颜色表示选中。
- 状态：可达/运行中、超时/待处理、失败/已停止有文字和图形标记。未检测显示“未检测”，不显示 0ms。
- 表单：PC 标签与控件分栏，控件不盲目拉满超宽屏；手机文字输入/选择使用“标签 → 说明 → 全宽控件”。开关行保留左右布局，长标签允许自然换行。
- 手机页面标题区最多保留 1 个主要操作和 1 个次要操作，其余低频操作进入明确命名的更多菜单；不隐藏页面导航。
- 订阅编辑、连接详情、日志详情：PC 右侧详情栏或对话框；手机全宽抽屉/独立详情面板，不把桌面对话框硬塞进小屏。
- 加载不清空旧内容；显示“更新中”。异步操作结束后明确显示结果；异常不伪装为成功，失败可重试。
- 确认删除、关闭全部连接、恢复备份时说明对象与影响；导入和普通切换不引入多余确认。

### 代理页修订 v3：参考上游单节点测速（历史稿，布局由 V4 取代）

核对上游 `proxies/card.dart` 的 `ProxyDelayText`、`ProxyCard` 与 `proxies/common.dart` 的 `proxyDelayTest`：点击卡片选择出口；点击延迟数字/闪电图标独立检测，不切换当前节点。上游未测显示闪电、请求中显示动画、完成显示延迟或 Timeout。

- 策略组改为紧凑横向页签，去掉占空间的组侧栏与两层大卡片结构；手机四个示例策略组一行可见。
- 节点卡片按上游结构分为名称区、协议/延迟区；保留地区标记、清楚的选中勾选和浅绿底色。
- 名称区是选择按钮，右下延迟是独立按钮；使用两个并列按钮，禁止嵌套 button。点击延迟不会冒泡成选择节点。
- 每项可单测、复测；未测、检测中、成功、超时四态明确。检测时仅禁用该节点的检测按钮，其余节点仍可操作。
- 保留“测试本组”，与单节点测试分工清楚；不因测速而切换默认出口。
- 延迟按钮手机高度至少 44px，带可访问名称“单独测试某节点的连通性”；时延是请求响应时间，不代表带宽或 ICMP Ping。
- 卡片与紧凑列表两种视图都提供同样的单测入口；超时保持可点击重试。
- 策略子组的实际实现需要测试其当前出口；REJECT/PASS 等不可测项不应显示虚假的测速值。设计稿只演示交互，未调用路由器。

上游代码参考位于本地 `bettbox-src/lib/views/`，对应远端 [Bettbox](https://github.com/appshubcc/Bettbox)。交互和信息结构按路由器适用范围取舍，并非直接套用 Flutter 手机界面。

### 流量统计卡

- 采用上游环形图语义：深绿表示上传，浅绿表示下载；圆心显示累计总量，旁边明确显示两项累计数值、单位与占比。
- 与实时速度分开。KB/s、MB/s 放在实时指标；B、MB、GB 放在流量统计，不将速率和累计量混用。
- 默认范围为“本次核心启动以来”，重启归零；统计 Mihomo 处理的连接，不能将其称为整台路由器总流量或全部 LAN 传输，也不等于订阅套餐用量。
- 环形图按真实占比绘制，不能为了好看固定画成 50/50。两项都为零时显示中性空环、0.00 B 和未知占比，避免暗示不存在的上传下载量。
- 1400px 起：流量统计、网络检查、内网 IP 同行，网络检查获得更宽空间。700–1399px：流量统计与内网 IP 同行，网络检查下一行。手机：独立流量统计卡位于实时指标之后，保留完整两项数字。
- 首轮设计示例：上传 10.41 MB（5.3%）、下载 187.55 MB（94.7%）、合计 197.96 MB；均非设备实测。

## 5. 状态与边界

独立设计稿提供模拟状态示例；正式页面必须按真实 API 返回显示状态，不将示例数据带入运行界面。

- 核心停止：统计显示“—/核心未运行”，不将旧值当作当前值；仍可查看设置、订阅与日志。
- 网络检查失败：保留最后一次结果并标注过期/失败时间，不生成成功地区或出口 IP。
- 连通性：区分检测中、可达、HTTP 异常、超时、无法解析；可达不等于账户可用或流媒体解锁。明确由路由器发起及使用的路由策略。
- 未测延迟不显示 0ms，超时不参与“最快”排序；切换节点后刷新当前节点标记。
- 更新/恢复：标注执行状态和错误，保留可重试操作；不为尚未实现的后台能力承诺成功。
- 日志：优先使用核心级别字段，syslog 作为回退；正文出现 error 不等于 error 级别。
- 订阅、脚本、资源的编辑能力在设计稿中演示组织方式；正式实现需同时验证 RPC 和权限，不能只把设计按钮接成假成功。

## 6. 设计验收

以真实浏览器 viewport 检查 320、360、390、430、768、1024、1600px。

1. 所有页面 document.scrollWidth 不超过 viewport，不用 overflow-x:hidden 掩盖错误布局。
2. 手机九个主页签保持横排、两行可见；不依赖系统桌面页面缩放。
3. 输入不越界；44px 主操作能点击；长策略组、节点、域名、IPv6 和错误消息不会顶宽页面。
4. PC 边距遵守 24px；手机边距 12px；面板对齐，不叠加空白。
5. 固定操作栏不遮挡内容；软键盘/安全区适配在正式真机实施阶段继续验证。
6. 独立设计稿与运行页面分开：设计预览使用模拟数据；LuCI 正式页面连接生产 API。当前九页已经完成实现，验收详情见 [UI 实现记录](UI_IMPLEMENTATION.md)。

V4 策略组通过纵向卡片展开，不使用横向组页签；九个应用主页签仍为两行全部可见。流量统计表示本次核心启动以来处理的流量，内核内存使用进程 RSS，两者均不是设备全部流量或订阅套餐用量。

## 界面文案（用户偏好）

页面只保留标题、数据、操作和必要状态。移除页面副标题、指标解释、统计口径脚注、操作教学、重复的面板说明和装饰页脚，不再增加“重启归零”“仅统计核心处理的流量”一类说明小字。错误原因和删除/恢复等操作后果按需显示。

## 代理图标保留规则

必须读取订阅经 Mihomo `/proxies` 返回的 `icon` 字段，覆盖策略组标题、当前选中出口和节点卡片。自定义图标优先；未提供或图片加载失败时显示对应类型的默认 SVG，不出现破图。不得在重新设计时将这条数据链替换成固定示意图标。预览使用本地图片模拟 `icon` 字段，图片尺寸固定且不影响名称、选择和测速。

## 代理页 V4（当前正式实现）

- 参考 [zashboard](https://github.com/Zephyruso/zashboard) 的可折叠策略组与独立延迟交互，沿用本站绿色、字体和间距。
- 900px 起组卡片分为两列；更窄时按配置顺序排列为单列。600px 以下节点固定两列，外侧仅 12px 边距；卡片/列表同样支持独立检测。
- 组头包含订阅图标、组名、类型、数量、当前选择到最终出口的链路与本组检测；折叠不隐藏当前链路。长名称截断并提供完整 title，不让节点名撑宽卡片。
- 默认展开前两组，记录用户的展开状态；支持全部展开/收起、组/节点搜索、默认/延迟/名称排序、视图切换、测试地址设置。筛选不改写已保存的展开状态。
- 选中节点采用主题强调色填充；浅色使用深绿白字，深色遵循主题的浅绿深字。测试按钮独立于名称选择，支持单项、右键、本组和全部检测。
- 全页队列最多同时执行两项，按实际出口去重；展示排队/检测/延迟/超时/失败。控制器不可达显示紧凑状态条，已有数据留在原位，允许重试。
- 正式实现使用真实控制器和诊断 RPC；预览数据只留在设计目录。代码和验证记录见 [UI 实现记录](UI_IMPLEMENTATION.md)。
